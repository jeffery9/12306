# 7. Seat Segment Bitmap

假设一趟车：

```text
北京 → 天津 → 济南 → 南京 → 上海
```

有：

```text
4 segments
```

那么：

```text
0000 = 全部空闲
```

如果：

```text
天津 → 济南
```

被占用：

```text
0100
```

如果：

```text
天津 → 南京
```

被占用：

```text
0110
```

定义：

```java
public final class SegmentMask {

    public static long rangeMask(
        int fromSegment,
        int toSegment
    ) {
        long length = toSegment - fromSegment;

        long mask = (1L << length) - 1;

        return mask << fromSegment;
    }
}
```

例如：

```text
from = 1
to   = 3
```

得到：

```text
0110
```

# 9. Redis Cluster Key Design

必须避免：

```text
seat A
seat B
seat C
```

随机落在不同 Redis Slot，导致无法原子操作多个 Key。

因此采用 Redis Hash Tag：

```text
r:{scheduleId}:seat:{seatId}
r:{scheduleId}:reservation:{reservationId}
```

例如：

```text
r:{123456}:seat:8001
r:{123456}:seat:8002
```

Redis Cluster 会保证：

```text
{123456}
```

部分进入同一个 Hash Slot。

这样才能使用 Lua 对同一运行日的相关库存进行原子操作。

# 10. Redis Lua Reservation

核心 Lua：

```lua
local seatKey = KEYS[1]
local reservationKey = KEYS[2]

local requestMask = tonumber(ARGV[1])
local reservationId = ARGV[2]
local ttl = tonumber(ARGV[3])

local occupied = redis.call("GET", seatKey)

if occupied == false then
    occupied = 0
else
    occupied = tonumber(occupied)
end

-- 已经存在占用
if bit.band(occupied, requestMask) ~= 0 then
    return 0
end

-- 原子设置占用
local newValue = bit.bor(occupied, requestMask)

redis.call(
    "SET",
    seatKey,
    newValue
)

redis.call(
    "HSET",
    reservationKey,
    "reservation_id",
    reservationId,
    "mask",
    requestMask,
    "state",
    "HELD"
)

redis.call(
    "EXPIRE",
    reservationKey,
    ttl
)

return 1
```

生产版本还需要处理：

- reservation ownership；
- release；
- confirm；
- rollback；
- version；
- Lua 脚本 SHA；
- Redis failover。

# 11. 更重要的问题：不能直接用 SET 覆盖 Seat 状态

上面的代码是说明原子思想。

生产实现应该避免：

```text
SET newValue
```

覆盖其他 Reservation 的复杂状态。

更合理的是把：

```text
segment occupancy
```

与：

```text
reservation ownership
```

分开。

例如：

```text
seat occupancy bitmap
```

只表示：

```text
哪些 segment 被占用
```

而：

```text
reservation:{id}
```

记录：

```text
是谁占用了哪些 segment
```

这样 Release 才能精确进行：

```text
oldBitmap & ~reservationMask
```

同时必须验证：

```text
当前 ownership == reservationId
```

否则不能释放。

# 27. 数据库防超卖

最终必须在 MySQL 再次验证。

例如：

```sql
UPDATE seat_segment
SET reservation_id = ?,
    state = 'HELD',
    version = version + 1
WHERE schedule_id = ?
  AND seat_id = ?
  AND segment_no >= ?
  AND segment_no < ?
  AND state = 'AVAILABLE'
  AND reservation_id IS NULL;
```

但是这里存在一个重要问题：

一次 UPDATE 可能更新多个 segment。

因此必须验证：

```text
affected_rows
==

```





# 83. 最关键的一点：Redis 预扣不是最终一致性方案

```text

    ≠
```

```text
             │
             ▼

             │

```

```text
Read Projection
```

而不是把这几个东西混成一个“库存系统”。
