# 🌌 12306 高并发区间票务分配系统非功能性需求与系统安全约束规范 (Non-Functional Requirements & Safety Constraints)

本自述与规格文件定义了 12306 系统在物理动力学、社会博弈防护、极速应急避险、高并发读写 SLA 以及客票收益管理等五个刚性维度的**非功能性需求 (NFRs)** 与**安全红线约束**。

所有后续子系统扩展、核心分配算法重构及局端网络对接，必须严格遵守本规范设定的物理与逻辑约束边界。

---

## 1. 物理动力学与重力载重防过载红线 (Physical Loading & Axle-Weight Guard)

高速动车组（时速 300 - 350km/h）不同于地铁或慢速普速列车。其高速运行、弯道倾覆防范以及紧急制动距离，对车厢总重和重力分布有极其严苛的物理限制。

```text
  [ 350km/h 弯道重力与向心力力学模型 ]
  
                   站立乘客溢出重力 (增加重心上移，破坏车辆侧滚稳定性)
                         │
                         ▼ ▼ ▼ ▼
                     ┌─────────────┐  ───► 弯道离心力
                     │  高铁车厢   │ 
                     └──────┬──────┘
                            │
               ┌────────────┴────────────┐
               ▼                         ▼
         [ 空气弹簧传感器 A ]      [ 空气弹簧传感器 B ]  ───► 实时压强监测 (压强 P)
  ───────┬─────────────────────────┬──────────────────────────────────────────
         ▼                         ▼
       [ ATP/LKJ 列车主控微电脑 ] ───► 若超员率 > 20% (P > 阈值) ───► 强制切断动力，拒绝开车
```

### 📏 1.1 刚性安全指标 (NFR-PHY-01)
*   **物理超员率红线**：单节二等座/无座车厢在任何时刻的超员率（Overload Ratio）**严格限制在 15% - 20% 之间**（依具体车底基准型号而定）。
*   **空气弹簧压强联动**：车体转向架两侧空气弹簧（Air-Springs）实时上报重力压强数据。一旦传感器数据超过报警阈值，车载列车运行控制系统（ATP/LKJ）将拉起硬件联锁，**拒绝向牵引变流器下发动力使能信号，列车自动锁死无法启动**。
*   **算法限制**：票务系统发售的无座（站票）总量，在底库层级必须乘以严格的安全折减系数，**其上限为该列车物理载重上限的 10%，严禁由外部请求溢出**。

## 2. “买短乘长”社会博弈黑洞防范 (Anti-Game-Theory Hack Policy)

当热门长途直达车票（如北京-上海）瞬发售罄时，旅客在利益驱使下，会采取“社会博弈投机”——即通过购买极易买到的极短途无座票（如北京-天津）混上列车，强行越站乘坐到终点。

### 🚨 2.1 经典博弈崩溃闭环 (The Breakdown Loop)

```text
   [ 投机旅客 A ] ──────► 购买「北京-天津 (20元)」无座票混上车 ──────► 抵达天津后「强行赖车不走」
                                                                          │
                                                                          ▼
   [ 济南站台上 ] ◄───── 列车到达济南，因超载触发空气弹簧报警 ◄───── [ 旅客 A 强行越站 ]
         │               ( 列车动力锁死，在站台无限延误 )
         ▼
   [ 合法旅客 B ] ──────► 购买了全款「济南-上海 (400元)」有座票 ──────► 因列车超员被列车员阻拦在站台，无法上车
```

### 🛡️ 2.2 防护算法设计与逻辑约束 (NFR-SEC-01)
为了切断上述系统性瘫痪的闭环，12306 必须在软件策略上限制“买短乘长”的空间：

1.  **无座票区间定向倾斜**：
    无座站票的配额**不向超短途区间（如运行时间小于 45 分钟的短途腿）开放发售**。无座票配额优先投递给中长途旅客，从源头上提高短途上车门槛。
2.  **联程路由（EPIC-06）引导**：
    当直达票罄时，购票系统宁愿调用「同车换座」或「中转联程」等更人道的算法，将碎片运力组织给旅客，也**绝对不采用无限发售短途站票的粗暴策略**。
3.  **严格黑名单惩罚机制**：
    一旦车载乘务员端点手持机（POS）扫描发现旅客未在票面到站下车（强行越站），系统对超出段收取 **1.5 倍加成票价 + 违章乘车乘车费**，并将该身份证件拉入 180 天受限购票黑名单。

## 3. 极速紧急疏散与空间走廊安全 (Emergency Evacuation Corridor Bounds)

高铁车厢内的物理走廊、洗手间前室、通道宽度属于国家铁路标准刚性限制。

```text
  [ 车厢物理空间通道布局 (Corridor Bottleneck) ]
  
  ┌──────────┐                     走廊物理净宽仅 55-60 厘米
  │  二等座  ├───────┐            ┌───────────────────────────────┐
  │  3+2 布局│ 席位1 │            │ 走廊宽度限制：仅容单人/餐车通行│  ──► 若无座站立人员过载
  ├──────────┤       ├────────────┤                               ├─► 极端火灾/起火时将彻底堵死
  │  走 廊   │  通道 │ 紧急逃生门  │ 严禁堆放行李、严禁无座乘客阻断 │  ──► 诱发灾难性挤压踩踏
  └──────────┘       └────────────┴───────────────────────────────┘
                     逃生黄金 60s
```

### 🚑 3.1 疏散安全性指标 (NFR-SAF-01)
*   **逃生黄金时间**：车厢设计规范要求，在突发火灾、高压电弧短路、脱线报警等特情下，全车旅客必须在 **60 秒内通过物理车门全部疏散到路基安全处**。
*   **无座空间密度上限**：在发售极少量无座票时，系统必须基于车厢剩余物理面积进行安全测算，每平方米站立人数 **不得大于 2.5 人/平方米**。
*   **车门区域净空**：物理车门、手动破窗点（安全锤放置区）前方的物理站立人数上限必须在系统参数中配置为 `0`（强制不能发售针对这些车厢死角位置的占位标识）。

## 4. 高并发读写分离与最终一致性 SLA (CQRS & Read-View SLA)

本项目 MVP 采用 **CQRS（读写分离）与 EDA（事件驱动）** 作为高吞吐抗撞击的基石。

### ⚡ 4.1 核心性能及延迟红线 (NFR-PERF-01)

在亿级大客流高频查询和抢占的春运/国庆场景下，读写视图必须具备高等级的吞吐量与一致性延迟保护：

```text
  【写模型事务落库】──► ( SRE SLA: <= 50ms )
            │
            ▼
  【发件箱 (Outbox) 轮询撈取】──► [SKIP LOCKED 高性能捞取] ──► ( SRE SLA: <= 100ms )
            │
            ▼
  【Kafka 投递与高并发重组】──► ( SRE SLA: <= 10ms )
            │
            ▼
  【投影器 (Projector) 刷写 Redis 读缓存】──► ( SRE SLA: <= 50ms )
```

*   **最终一致性（Eventual Consistency）整体 SLA**：
    从写侧 MySQL 扣减完成、生成 Outbox 事件，到读侧 Redis Bitmap 和 Availability 查询缓存被刷写成功的**最大端到端延迟，必须严格控制在 150 毫秒以内**（平均值应 `< 50ms`）。
*   **首道读过滤延迟**：
    高并发 Redis Lua 检票脚本、段位图碰撞检索（Query Side）的 **首包响应延迟必须 `< 5` 毫秒**。
*   **读视图自愈（Self-Healing）**：
    当发生极其罕见的网络抖动或 Kafka 分区重平衡（Rebalance）导致投影延时时，若读缓存发生 Miss，读侧接口必须在 **20 毫秒内回源重算**并热写 Redis，确保后续请求不发生次生雪崩。

## 5. 商业收益管理与客票价值对齐 (Economic Yield Optimization)

铁路系统的运行具有极高的固定运行成本（折旧、高压电网、路轨养护、司乘工资），而单次行程的边际成本极低。

### 💰 5.1 收益对齐约束 (NFR-ECO-01)
*   **价格/座位保护**：
    无座票由于乘坐体验断崖式下跌，且占用了走廊公共空间，若针对短途无限发售，在票价与有座同价的规定下（如京津无座也是 50 元），会导致高票价长途贯通流失（如京沪 1000 元）。
*   **算力与商业错配控制**：
    系统必须在 API 边缘节点直接拦截不合理的短途高频请求，节约写侧宝贵的物理行锁（Row Locks）算力，将其100%预留给高收益、高里程的长途交易，实现计算资源与商业价值的完美对齐。
